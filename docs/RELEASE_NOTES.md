# 릴리스 노트

## 1.20.0 (2026-11-05)

재생 화면에 음향 이퀄라이저와 화면 효과를 넣었다.

### 1. 음향 이퀄라이저

- 10개 밴드(31Hz–16kHz, ±12dB, 0.5dB 단위)와 프리셋(평탄, 저음강조, 고음강조, 목소리, 록, 팝, 영화)을 제공한다.
- 재생 소리만 바뀌며 원본 파일은 바뀌지 않는다. 설정은 이 PC에 저장된다.
- 재생을 시작해야 소리 처리 그래프가 만들어진다. 그 전에는 원래 소리가 나온다.

### 2. 화면 효과

- 흑백, 세피아, 반전, 빈티지, 시원하게, 따뜻하게, 부드럽게, 선명한 대비 필터.
- 가장자리 어둡게(비네팅), 스캔라인을 따로 켤 수 있다.

### 3. 음량 미터

- 재생 중 실제 소리 크기를 보여준다. 멈추면 0으로 돌아간다.

### 수정

- 미디어 프로토콜이 교차 출처 요청(CORS)과 Range 사전 요청을 받도록 했다. 소리 그래프가 교차 출처 미디어를 무음으로 만들지 않도록 하기 위해서다.

### 검증

- 단위 테스트 401개(50개 파일), E2E 44개 통과. 라이브러리 E2E에 이퀄라이저·효과·미터 확인을 추가했다.

## 1.19.0 (2026-11-05)

영상 편집기의 완성도를 높이는 다섯 가지를 넣었다: 원본 다시 연결, 휴대폰 회전과 인터레이스 처리, 미리보기와 내보내기 위치 일치 검증, 구간만 내보내기, 자막 파일 가져오기.

### 1. 원본 파일 다시 연결

- 원본 파일을 옮기거나 이름을 바꾸면 편집 화면 위에 "원본 파일을 찾을 수 없습니다" 안내가 나오고, 각 파일마다 "다시 찾기" 버튼이 있다.
- 새 파일을 고르면 같은 경로를 쓰는 클립, 트랙 클립, 배경 음악, 워터마크가 모두 바뀌고, 원본 구간은 그대로 남는다. 새 파일이 짧으면 끝 시점을 줄이고 알린다.
- 재연결은 실행 취소 한 단계로 남는다.

### 2. 휴대폰 회전과 인터레이스

- **인터레이스 제거**: 등록할 때 줄무늬(인터레이스) 영상을 자동으로 감지한다. 속성 패널에서 켜고 끌 수 있고, 켜면 렌더 때 `yadif` 필터로 필드를 프레임으로 바꾼다. 프레임 속도는 그대로다. 실제 인터레이스 파일로 결과가 더 이상 인터레이스가 아님을 확인했다.
- **회전 메타데이터**: 원본의 표시 크기를 회전 정보에 맞춘다. 90도나 270도로 저장된 영상은 가로와 세로를 바꿔 등록한다. 단위 테스트로 확인했고, 실제 휴대폰 회전 파일로는 이 환경에서 만들지 못해 Windows에서 확인해야 한다.

### 3. 미리보기와 내보내기의 위치·크기 일치

- 4:3 영상을 16:9 캔버스에 맞춘 실제 렌더 결과를 픽셀로 재서, 미리보기 계산과 가로 비율이 1% 안에서 같은지 확인하는 테스트를 추가했다.
- 색과 세부 모양은 검사하지 않는다. 위치와 크기만 검사한다.

### 4. 구간만 내보내기

- 타임라인에서 구간을 고른 뒤 "구간만 내보내기"를 누르면 그 구간만 파일로 만든다. 파일 이름은 "-range"가 붙는다.
- 저장된 프로젝트는 바뀌지 않는다. 구간 밖을 잘라낸 복사본으로 렌더한다. 구간이 없으면 버튼이 비활성이다.
- 같은 자르기 규칙(`src/shared/timelineCut.ts`)을 화면과 메인 프로세스가 함께 쓴다.

### 5. 자막 파일 가져오기

- 클립을 고르고 "자막 파일 가져오기"를 누르면 SRT, VTT, ASS, SSA 파일을 고를 수 있다. 2MB 이하만 읽는다.
- 자막 시각은 **원본 영상의 시각**으로 본다. 배속과 원본 시작 위치를 반영해 클립 안 시각으로 바꾸고, 글자 표시로 넣는다.
- 클립 하나에는 최대 500개까지 넣을 수 있다 (이전 20개).

### 검증

- 단위: 표시 크기 계산, 인터레이스 필터 위치, 자막 시각 환산과 범위 밖·빈 글자 제외와 최대 개수, 원본 다시 연결(같은 경로 모두 바꾸기, 짧은 파일, 쓸 구간 없음, 없는 참조 찾기).
- 통합 (실제 FFmpeg): 인터레이스 파일 감지와 제거 후 결과, 구간만 내보내기의 길이와 프로젝트 불변, 원본을 옮긴 뒤 찾기와 다시 연결과 저장, 4:3 → 16:9 위치 일치.
- E2E: 구간이 없을 때 구간만 내보내기 버튼이 비활성, 클립 속성에 인터레이스 제거와 자막 가져오기 표시.

### 제한

- 휴대폰 회전 영상은 이 환경에서 실제 파일로 만들지 못했다. Windows에서 세로 휴대폰 영상으로 확인해야 한다.
- 원본 다시 연결과 자막 가져오기는 파일 선택 창을 쓰므로 자동 테스트에서는 흐름의 일부만 확인했다(찾기 버튼 표시, 서버 처리). 실제 선택 창 동작은 수동 확인이 필요하다.
- 위치 일치 검증은 위치와 크기만 본다. 색과 텍스트의 모양은 미리보기가 근사치다.
- 자막은 글자 표시로 들어간다. 자막 파일의 스타일(ASS 색과 위치)은 반영하지 않는다.

## 1.18.0 (2026-11-04)

클립마다 소리를 정리하는 기능을 넣었다: 잡음 줄이기와 보컬 처리(좌우 채널 방식). 완전한 음원 분리(AI)는 아직 없다.

### 잡음 줄이기

- 속성 패널 "소리 정리"에서 끔 / 약하게 / 강하게를 고른다. FFmpeg 내장 `afftdn` 필터를 쓰며 추가 모델 파일이 필요 없다.
- 음성 전체에 같은 강도로 적용되므로 강하게 하면 목소리가 얇아질 수 있다.

### 보컬 처리 (스테레오 원본만)

- **보컬 줄이기 (가라오케)**: 좌우 차이만 남긴다. 가운데에 있는 목소리는 크게 줄고, 한쪽에 있는 악기 소리는 남는다.
- **가운데만 남기기 (보컬 위주)**: 좌우를 합쳐 가운데 성분만 남긴다.
- 모노 원본에서는 채널을 나눌 수 없으므로 옵션을 막고 이유를 보여 준다. 원본을 넣을 때 채널 수를 기록한다.
- 보컬 처리는 가운데 소리가 한 덩어리로 있을 때 잘 된다. 베이스와 드럼이 가운데 있으면 함께 줄어든다. 완전한 분리가 필요하면 AI 음원 분리가 필요하다.

### 적용 위치

- 소리 정리는 내보내기에만 반영되고 실시간 미리보기에는 반영되지 않는다. 적용 순서는 배속, 보컬 처리, 잡음 줄이기, 볼륨 순이다.

### 검증

- 단위: 잡음 필터 값, 보컬 채널 연산 식, 모노 거부, 정리 필터 순서, 렌더 계획에서 배속 뒤·볼륨 앞의 위치.
- 통합 (실제 FFmpeg): 가운데 소리만 있는 파일은 "보컬 줄이기" 결과가 -50dB 아래로 사라진다. 한쪽에만 있는 소리는 줄이기 후 약 3dB 커지고(양쪽 복사), 가운데 남기기 후 약 3dB 작아진다(진폭 절반). 모노 원본은 옵션을 지정해도 결과가 같다.
- E2E: 잡음 줄이기 선택 상자에서 강하게를 고르면 값이 바뀌고, 보컬 처리 선택 상자와 안내 문구가 보인다.

### 제한

- 잡음 줄이기는 음성 구간을 구분하지 않고 전체에 적용한다. 음악이 섞인 소리에서는 음악도 함께 줄어든다.
- AI 음원 분리(목소리와 배경음 완전 분리)는 모델 파일과 추론 엔진이 필요해 아직 넣지 않았다.
- 미리보기에는 소리 정리가 반영되지 않는다.

## 1.17.0 (2026-11-04)

Clipchamp 같은 일반 편집기와 비교해 빠져 있던 편집 기능을 넣었다: 우클릭 메뉴, 복사·붙여넣기·복제, 프레임 고정, 클립 페이드, 표시 이름과 길이 편집, 선택 구간만 재생, 화면에 맞추기, 5초 이동, 미리보기 전체 화면.

### 분할과 구간 보기

- **분할**: 재생 헤드에서 S 키 또는 "재생 헤드에서 분할", 같은 길이로 N등분, 초 간격 나누기는 이전부터 있었다.
- **선택 구간만 보기 (새로 추가)**: 구간(I·O 또는 눈금 끌기)을 고른 뒤 "구간만 재생"을 누르면 그 구간만 재생하고 끝에서 멈춘다. 프로젝트는 바뀌지 않는다. "구간만 남기기"는 이전부터 있었는데, 나머지를 잘라 프로젝트를 바꾸는 기능이다.

### 클립 편집

- **우클릭 메뉴**: 복제(Ctrl+D), 복사(Ctrl+C), 붙여넣기(Ctrl+V, 선택한 클립 뒤), 분할, 프레임 고정(F), 이름·길이·페이드 편집, 삭제(Delete). 바깥을 누르거나 Esc 로 닫힌다.
- **프레임 고정**: 재생 헤드 위치의 한 장면을 멈춰 보여 준다. 클립이 앞·고정·뒤 세 조각이 되고, 고정 길이는 기본 3초이며 속성 패널에서 바꾼다. 고정 조각에는 소리가 없다.
- **페이드 인·아웃**: 속성 패널에서 클립마다 영상과 소리를 함께 페이드한다. 최대 길이는 클립 길이의 절반이다. 미리보기에도 반영된다.
- **표시 이름**: 타임라인에 보이는 이름을 바꾼다. 파일 이름은 그대로다.
- **길이 편집**: 속성 패널에서 길이를 초 단위로 정한다(배속 반영). 고정 클립은 고정 길이를 바꾼다.
- **썸네일**: 클립 폭에 맞춰 원본 프레임 최대 12장을 클립 배경에 깐다.

### 재생과 보기

- 재생 줄에 ◀ 5초, 5초 ▶ 버튼을 추가했다.
- "화면에 맞추기"는 타임라인을 가로 폭에 맞춘다.
- "전체 화면"은 미리보기를 전체 화면으로 연다. 이를 위해 전체 화면 권한만 허용했고, 나머지 권한은 그대로 거부한다.

### 검증

- 단위: 클립 시간 규칙, 이름, 페이드 배율, 프레임 고정 세 조각, 배속 클립의 고정 위치, 복사본, 썸네일 개수·시각, 렌더의 페이드 필터와 고정 프레임 입력, 미리보기 페이드.
- 통합 (실제 FFmpeg): 흰색 영상의 시작 페이드 직후는 어둡고(0.02초 밝기 40 미만), 중간(0.5초)은 밝으며, 고정 구간(1.2초, 2.3초)은 같은 장면이 흰색으로 유지되고, 고정 구간의 소리는 -60dB 미만이다. 전체 길이는 3.5초다.
- E2E: 우클릭 메뉴, Ctrl+D·Ctrl+C·Ctrl+V와 실행 취소, F 키 프레임 고정, 화면에 맞추기, 이름 바꾸기, 선택 구간만 재생이 끝에서 멈추는 것, 전체 화면 버튼.

### 제한

- 구간만 재생은 미리보기이므로 근사치다. 결과 영상과 색·밝기 차이는 내보내기로 확인해야 한다.
- 프레임 고정 클립에는 배속·회전·필터·움직임 키프레임을 쓰지 않는다.
- 썸네일은 원본 프레임이라 효과와 페이드는 보이지 않는다.
- 페이드 곡선은 직선이다. 전환 모양(닦기, 밀기)은 여전히 교차 페이드로 흉내 낸다.

## 1.16.0 (2026-11-04)

영상 합치기를 실사용 수준으로 다듬었다: HDR·10비트 원본 동의 절차와 톤 매핑, 무손실 합치기, 클립 사이 음량 맞춤, 편집기 하드웨어 인코더. 가변 프레임 속도 영상 합치기도 자동 테스트로 확인했다.

### HDR·10비트 원본

- 클립을 넣을 때 HDR(PQ·HLG)과 비트 깊이를 기록하고, 타임라인에 "HDR" 또는 "10비트" 표시를 붙인다. 출력 설정에 경고가 나온다.
- 편집 결과는 SDR 8비트(BT.709)다. 출력 설정에서 "HDR·10비트 원본을 SDR 8비트로 변환"에 동의하지 않으면 내보내기를 멈추고 어떤 파일이 어떻게 바뀌는지 알린다 (조용한 HDR→SDR, 10→8비트 변환 금지 원칙). 이전에 만든 프로젝트의 클립도 내보내기 직전에 원본을 다시 검사한다.
- 동의하면 HDR 원본을 톤 매핑한다(zscale → hable 톤 매핑 → BT.709). 톤 매핑 필터가 없는 FFmpeg 이면 이유를 알리고 멈춘다. 미리보기 렌더는 동의 없이 진행하며 결과가 아니다.

### 무손실 합치기

- 출력·진행의 "무손실 합치기"에서 가능 여부를 확인하고, 되면 재인코딩 없이(-c copy) 몇 초 만에 합친다. 화질이 그대로다. 결과는 원본과 같은 형식으로 "-merge" 이름이 붙는다.
- 조건: 클립 두 개 이상, 파일 전체 사용, 속도·회전·보정·텍스트·전환·움직임·음량 변경 없음, 배경 음악·워터마크·추가 트랙 없음, 캔버스와 프레임 속도 자동, 영상 코덱·크기·픽셀 형식·프레임 속도·음성 코덱·표본 주파수·채널 수가 모두 같음. 맞지 않으면 이유를 하나씩 보여 준다.
- 결과 길이가 원본 합과 다르면 실패로 보고 결과를 남기지 않는다.

### 클립 사이 음량 맞춤

- 출력 설정에서 켜면 클립마다 EBU R128 기준 -16 LUFS 로 맞춘 뒤 잇는다. 작은 소리와 큰 소리 클립의 차이(20dB 이상)가 3dB 안으로 줄어드는 것을 확인했다. 실시간 미리보기에는 반영되지 않는다.

### 하드웨어 인코더

- 출력 설정에서 켜면 이 PC 에서 확인된 하드웨어 인코더(NVENC·QSV·AMF)로 내보낸다. 실패하면 CPU 인코더로 자동으로 다시 렌더한다. 품질 값은 CRF 대신 인코더별 기본값(압축 기능과 같은 표)을 쓴다.
- 실제 GPU 에서의 결과는 확인하지 못했다 (테스트 환경에 GPU 없음). 실패 후 CPU 로 다시 렌더하는 경로는 확인했다.

### 가변 프레임 속도 영상

- 앞 1초는 30fps, 뒤는 10fps 인 가변 프레임 영상과 고정 프레임 영상을 합친 결과에서 영상·음성 길이 차이가 0.1초 안이고, 결과가 30fps 고정임을 확인했다.

- 미리보기: 초점을 기준점으로 같은 배율로 확대한다. 이 방식이 렌더의 잘라 내기 위치와 같은 식이라는 것을 테스트로 확인했다.

- 미리보기: 재생 중 오버레이 이미지의 가운데와 너비가 렌더 공식과 1% 안에서 같은지 확인했다.

### 제한

- 메인 클립 회전 키프레임, 트랙 클립 손떨림 보정·선명·노이즈 제거는 없다.

- **영상 트랙**("+ 영상 트랙"): 메인 트랙 위에 영상이나 이미지를 원하는 시간 위치에 겹친다 (화면 속 화면, 로고, 스티커). 위치·크기·불투명도를 정한다. 뒤에 만든 트랙이 위에 온다. 이미지는 5초로 놓이고 길이를 바꿀 수 있다.
- **오디오 트랙**("+ 오디오 트랙"): 효과음·내레이션 같은 소리를 원하는 위치에 놓고 음량을 정한다. 원래 음성과 섞인다(배경 음악의 원본 비율과 따로 간다).
- 트랙 클립은 끌어 옮기고(다른 클립 경계와 재생 헤드에 붙는다), 가장자리를 끌어 길이를 조절한다. 트랙은 끄거나 지울 수 있다. 최대 20개.
- 구간 삭제와 구간만 남기기는 모든 트랙에 같이 적용된다 (트랙 클립도 당겨지거나 나뉜다).

### 키프레임

- 트랙 클립의 가로·세로 위치, 크기, 불투명도, 음량에 키프레임을 넣는다. 키프레임 사이는 직선으로 바뀐다.
- 속성 옆 ◆ 버튼으로 재생 헤드 시점에 키프레임을 넣고 뺀다. 키프레임이 하나라도 있으면 슬라이더를 움직일 때 그 시점 키프레임이 자동으로 생기거나 바뀐다. 이전·다음 키프레임으로 이동할 수 있고, 고른 클립 위에 키프레임 위치가 ◆ 로 보인다.
- 렌더: 위치는 overlay 식, 크기는 프레임마다 다시 계산하는 scale, 불투명도는 geq 알파, 음량은 volume 식으로 넣는다. 크기가 바뀐 뒤에 geq 를 두면 FFmpeg 6 이 비정상 종료하는 것을 확인해, 불투명도를 먼저 처리하는 순서로 고정했다.
- 메인 트랙 클립의 키프레임(확대·이동 같은 켄번스 효과)은 아직 없다.

### 실행 취소

- 트랙 추가·삭제·끄기, 트랙 클립 추가·삭제·이동·조절, 속성과 키프레임 변경이 모두 실행 취소 대상이다. 끌기와 슬라이더는 한 번이 한 단계다. 키프레임 넣기·빼기는 한 번에 한 단계다.

### 호환성

- 이전 버전에서 만든 프로젝트와 .kcp 파일은 트랙이 없는 상태로 그대로 열린다.

### 제한

- 실시간 미리보기의 트랙 반영도 근사치다. 크기 키프레임은 미리보기에서 매끄럽게 보이지만 렌더는 짝수 픽셀로 맞춘다.

- **반영하지 않는 것**: 손떨림 보정, 선명하게, 노이즈 제거, 닦기·밀기·원 열림 같은 전환 모양(미리보기에서는 교차 페이드로 보인다), 100% 를 넘는 음량. 화면 아래에 "근사 미리보기" 표시가 나온다.

- **재생할 수 없는 형식**: 앱 화면이 재생하지 못하는 코덱(일부 HEVC, ProRes 등)이면 알리고 멈춘다. 내보내기에는 영향이 없다.

- 캔버스 크기 결정 규칙을 공용 모듈(`src/shared/editCanvas.ts`)로 옮겨 렌더 계획과 미리보기가 같은 함수를 쓴다.

### 제한

- 미리보기는 근사치다. 최종 결과는 내보내기나 "미리보기 렌더"로 확인해야 한다.

유튜브 임베드 재생을 넣었다. 이 기능에 맞춰 "외부 전송을 하지 않습니다" 원칙을 바꿨다. 기본값은 꺼짐이며, 설정에서 켜야 유튜브 서버에 접속한다.

- **이전 원칙**: 앱은 외부 전송을 하지 않는다. 렌더러의 네트워크 연결(`connect-src`)과 외부 리소스를 모두 막았다.
- **새 원칙**: 기본은 여전히 외부 전송 없음이다. 사용자가 설정에서 "유튜브 임베드 재생 허용"을 켠 경우에만 유튜브 호스트에 접속하며, 그 밖의 외부 접속은 허용하지 않는다.
- 렌더러 CSP 에 `frame-src https://www.youtube-nocookie.com` 만 추가했다. 네트워크 연결(`connect-src 'none'`)과 스크립트 출처(`script-src 'self'`)는 그대로다.

### 유튜브

- **주소 입력**: `youtube.com/watch?v=`, `youtu.be/`, `/embed/`, `/shorts/`, `/live/` 형식을 받는다. `t=90` 또는 `t=1m30s` 로 시작 위치를 지정할 수 있다. 다른 호스트와 잘못된 영상 ID 는 거부한다.
- **재생 조작**: 재생, 일시정지, -10초, +10초, 현재 위치 표시. 플레이어의 postMessage 로만 조작한다.
- **저장 없음**: 영상은 파일로 받지 않고 플레이어에서 스트리밍으로만 재생한다.
- **네트워크 정책**: 메인 프로세스가 유튜브 호스트 요청만 설정이 켜진 경우에 통과시킨다. 허용 호스트는 youtube-nocookie.com, youtube.com, ytimg.com, googlevideo.com, gstatic.com, google.com, googleapis.com 이다. 유튜브 요청에는 앱 식별용 Referer 를 붙인다. file:// 로 연 앱은 Referer 가 없으면 플레이어가 재생을 거부하기 때문이다.
- **YouTube Music**: 공식 임베드 재생을 제공하지 않아 앱 안에서 재생하지 않는다. 버튼으로 기본 브라우저에서 연다.

### 제한

- 이 빌드의 자동 테스트는 주소 해석, 정책, 메시지 형식, CSP, 설정 흐름만 확인한다. 실제 유튜브 재생은 네트워크가 있는 Windows 에서 직접 확인해야 한다. Referer 설정이 맞는지도 그때 확인해야 한다.
- 재생 시간 표시는 플레이어가 보내는 정보에 의존한다. 플레이어 메시지 형식이 바뀌면 위치 표시가 멈출 수 있다.
- 재생목록 주소, 유튜브 검색, 자막·품질 선택은 넣지 않았다.
- 유튜브 영상의 저장과 편집은 하지 않는다. 편집하려면 사용자가 직접 받은 파일을 기존 기능으로 여는 방식만 쓴다.
- URL 스트리밍(유튜브 외 주소)은 여전히 제외한다.

### 제한

- 라이브러리 미리보기 재생에는 자막을 표시하지 않는다. 자막 굽기(하드섭), 편집, 싱크 조정은 없다.

### 알려진 제한

- 설치 파일은 **서명되지 않았습니다**. Windows SmartScreen 경고가 나옵니다.
- 하드웨어 인코더는 실제 장치에서 검증하지 않았습니다. 실패하면 CPU 로 대체하고 결과에 기록합니다.
- 원본·결과 비교 화면은 아직 없습니다.
- HDR·Dolby Vision·인터레이스·알파 채널 영상은 재인코딩을 차단합니다 (원본 유지 모드만 가능).
- 샘플 추천의 SSIM 기준 0.97 은 초기 실험값입니다.
- 번들 FFmpeg 는 GPL v3 입니다. 배포자는 대응 소스 제공 의무를 이행해야 합니다 (`docs/RELEASE_CHECKLIST.md` 2절).

### 이 빌드에서 고친 결함 (코드 리뷰)

- 앱 시작 직후 도구 탐지가 끝나기 전에 등록한 작업이 `TOOL_NOT_FOUND` 로 실패하던 경합
- 재시도 후 재분석한 파일 상태를 변경 감지 기준에 반영하지 않아 `INPUT_CHANGED` 가 잘못 나던 문제
- 처리 시간 추정이 원본 유지 모드의 속도와 섞이던 문제 (모드별로 분리)
- 검증 단계(디코딩 검사, 패킷 수 계수)가 취소 신호를 받지 않던 문제
- 샘플 추천 계산 중 설정 변경·삭제·시작이 허용되던 경합
- 하드웨어 인코더에 10비트 `yuv420p10le` 를 넘기던 문제 (`p010le` 로 변경)
- 샘플 측정에서 MP4 후보가 CFR 로 바뀌어 기준본과 프레임이 어긋날 수 있던 문제 (`-fps_mode passthrough`)
- 창이 임의의 `file://` 주소로 탐색할 수 있던 문제 (앱 렌더러 주소만 허용)
- 확정 링크 후 임시 이름 삭제 실패를 치명 오류로 다루던 문제
- 초기 조회 전에 도착한 작업 변경 이벤트를 놓치던 문제
