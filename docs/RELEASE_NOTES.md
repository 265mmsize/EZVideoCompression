# 릴리스 노트

## 1.15.0 (2026-11-04)

1.14.0 에서 "아직 없다"고 적은 영상 편집 기능을 넣었다: 메인 클립 키프레임(확대·이동·음량), 트랙 클립 배속·회전·반전·보정, 트랙 사이 끌어 옮기기. 미리보기 배치가 렌더 공식과 맞는지도 자동으로 확인한다.

### 메인 클립 키프레임 (켄번스·음량)

- 클립 속성 아래 "움직임·음량 키프레임"에서 확대(1~4배), 가로 초점, 세로 초점, 음량에 키프레임을 넣는다. 확대와 초점은 처음 움직일 때 재생 헤드 시점에 키프레임이 생긴다. ◆ 로 넣고 빼며, 이전·다음 키프레임으로 이동하고, 한 번에 모두 지울 수 있다. 고른 클립 위에 ◆ 표시가 보인다.
- 렌더: 캔버스에 맞춘 뒤 프레임마다 확대하고 초점 위치에서 캔버스 크기로 잘라 낸다. 텍스트는 그 뒤에 그려 확대되지 않는다. 음량은 배속 뒤 volume 식으로 넣는다.
- 미리보기: 초점을 기준점으로 같은 배율로 확대한다. 이 방식이 렌더의 잘라 내기 위치와 같은 식이라는 것을 테스트로 확인했다.

### 트랙 클립 모양

- 영상·소리 트랙 클립에 배속(0.25~4배, 음높이 유지)을 넣었다. 이미지에는 배속이 없다.
- 영상·이미지 트랙 클립에 90도 회전, 좌우·상하 반전, 밝기·대비·채도를 넣었다. 렌더 순서는 메인 클립과 같다(회전 → 반전 → 보정), 그다음 투명도와 크기를 적용한다.

### 트랙 사이 옮기기

- 트랙 클립을 같은 종류의 다른 트랙(영상 ↔ 영상, 오디오 ↔ 오디오) 위로 끌어 놓으면 그 트랙으로 옮겨진다. 위치 이동과 트랙 바꾸기는 실행 취소 한 번에 되돌아간다.

### 자르기와 나누기에서 키프레임 유지

- 클립을 나누거나, 구간을 자르거나, 시작을 줄이면 조각 양 끝에 그 시점의 보간 값을 키프레임으로 넣어 원래 움직임이 그대로 이어진다 (메인 클립과 트랙 클립 모두). 배속이 있으면 시간을 배속만큼 환산한다.

### 검증

- 실제 렌더: 네 사분면 영상에서 확대 2배·초점 이동으로 화면 가운데가 빨강(왼쪽 위)에서 노랑(오른쪽 아래)으로 바뀌는지, 90도 회전한 이미지 오버레이 크기, 배속 소리 트랙을 픽셀과 스트림으로 확인했다.
- 미리보기: 재생 중 오버레이 이미지의 가운데와 너비가 렌더 공식과 1% 안에서 같은지 확인했다.

### 제한

- 메인 클립 회전 키프레임, 트랙 클립 손떨림 보정·선명·노이즈 제거는 없다.
- 미리보기 색과 픽셀 단위 일치, 실제 소리, Windows 에서의 성능은 여전히 직접 확인해야 한다.

## 1.14.0 (2026-11-04)

영상 편집기에 오디오 파형, 여러 트랙, 키프레임 편집을 넣었다. 렌더(내보내기)와 실시간 미리보기가 같은 규칙을 쓴다.

### 오디오 파형

- 메인 트랙 클립, 오디오 트랙 클립, 영상 트랙 클립의 음성, 배경 음악 행에 파형을 그린다. 자른 구간만 보인다.
- 메인 프로세스가 FFmpeg 로 모노 4kHz PCM 을 뽑아 초당 50개 피크로 줄이고 파일별로 캐시한다. 원본은 읽기만 하고, 중간 파일은 임시 폴더에 썼다가 지운다. 음성이 없는 파일은 파형 없이 계속 편집할 수 있다.

### 여러 트랙

- **영상 트랙**("+ 영상 트랙"): 메인 트랙 위에 영상이나 이미지를 원하는 시간 위치에 겹친다 (화면 속 화면, 로고, 스티커). 위치·크기·불투명도를 정한다. 뒤에 만든 트랙이 위에 온다. 이미지는 5초로 놓이고 길이를 바꿀 수 있다.
- **오디오 트랙**("+ 오디오 트랙"): 효과음·내레이션 같은 소리를 원하는 위치에 놓고 음량을 정한다. 원래 음성과 섞인다(배경 음악의 원본 비율과 따로 간다).
- 트랙 클립은 끌어 옮기고(다른 클립 경계와 재생 헤드에 붙는다), 가장자리를 끌어 길이를 조절한다. 트랙은 끄거나 지울 수 있다. 최대 20개.
- 구간 삭제와 구간만 남기기는 모든 트랙에 같이 적용된다 (트랙 클립도 당겨지거나 나뉜다).
- 결과 길이는 메인 트랙 길이다. 메인 트랙 끝을 넘는 트랙 클립 부분은 잘린다. 추가 트랙 클립에는 배속·회전·필터가 없다.

### 키프레임

- 트랙 클립의 가로·세로 위치, 크기, 불투명도, 음량에 키프레임을 넣는다. 키프레임 사이는 직선으로 바뀐다.
- 속성 옆 ◆ 버튼으로 재생 헤드 시점에 키프레임을 넣고 뺀다. 키프레임이 하나라도 있으면 슬라이더를 움직일 때 그 시점 키프레임이 자동으로 생기거나 바뀐다. 이전·다음 키프레임으로 이동할 수 있고, 고른 클립 위에 키프레임 위치가 ◆ 로 보인다.
- 렌더: 위치는 overlay 식, 크기는 프레임마다 다시 계산하는 scale, 불투명도는 geq 알파, 음량은 volume 식으로 넣는다. 크기가 바뀐 뒤에 geq 를 두면 FFmpeg 6 이 비정상 종료하는 것을 확인해, 불투명도를 먼저 처리하는 순서로 고정했다.
- 메인 트랙 클립의 키프레임(확대·이동 같은 켄번스 효과)은 아직 없다.

### 실행 취소

- 트랙 추가·삭제·끄기, 트랙 클립 추가·삭제·이동·조절, 속성과 키프레임 변경이 모두 실행 취소 대상이다. 끌기와 슬라이더는 한 번이 한 단계다. 키프레임 넣기·빼기는 한 번에 한 단계다.

### 호환성

- 이전 버전에서 만든 프로젝트와 .kcp 파일은 트랙이 없는 상태로 그대로 열린다.

### 제한

- 실시간 미리보기의 트랙 반영도 근사치다. 크기 키프레임은 미리보기에서 매끄럽게 보이지만 렌더는 짝수 픽셀로 맞춘다.
- 트랙 클립을 다른 트랙으로 끌어 옮기는 기능은 없다 (지우고 다시 넣는다).
- 실제 Windows 에서 4K 영상 여러 개를 겹쳤을 때의 미리보기 성능은 확인하지 않았다.

## 1.13.0 (2026-11-04)

영상 편집기에 실시간 미리보기 재생을 넣었다. 내보내기 전에 타임라인을 재생해 순서, 자른 구간, 전환, 텍스트를 바로 확인할 수 있다.

### 실시간 미리보기

- **재생·정지**: 타임라인 위 "▶ 재생" 버튼 또는 Space 키로 재생하고, 다시 누르거나 K 키로 멈춘다. 재생 헤드에서 시작하며 끝에서 누르면 처음부터 재생한다.
- **동작 방식**: 원본 클립을 영상 요소 두 개로 번갈아 재생한다. 다음 클립은 끝나기 1.5초 전에 미리 불러 두어 경계에서 끊김을 줄인다. 영상이 준비되지 않으면 시계를 멈추고 기다리므로 소리와 화면이 어긋나지 않는다.
- **반영하는 것**: 자른 구간, 배속(음높이 유지), 회전·반전, 캔버스 비율과 맞춤, 밝기·대비·채도, 텍스트(위치·크기·표시 구간·배경 상자), 워터마크, 클립 음량·음소거, 배경 음악(반복, 페이드 인·아웃, 원본 음성 비율), 전환(교차 페이드, 검정 페이드).
- **반영하지 않는 것**: 손떨림 보정, 선명하게, 노이즈 제거, 닦기·밀기·원 열림 같은 전환 모양(미리보기에서는 교차 페이드로 보인다), 100% 를 넘는 음량. 화면 아래에 "근사 미리보기" 표시가 나온다.
- **멈추는 경우**: 눈금이나 트랙을 누르거나, 재생 헤드 막대를 움직이거나, 화살표·Home·End 키를 누르면 멈춘다. 재생 중 편집한 내용은 바로 반영된다.
- **재생할 수 없는 형식**: 앱 화면이 재생하지 못하는 코덱(일부 HEVC, ProRes 등)이면 알리고 멈춘다. 내보내기에는 영향이 없다.

### 구조

- 캔버스 크기 결정 규칙을 공용 모듈(`src/shared/editCanvas.ts`)로 옮겨 렌더 계획과 미리보기가 같은 함수를 쓴다.
- 미리보기 계산은 순수 함수(`src/renderer/pages/previewMath.ts`)로 두고 테스트했다.
- 미리보기용 재생 주소 채널(`edit:mediaUrl`)은 영상·음성 파일만 토큰으로 열고 읽기만 한다. 음성 파일 형식(mp3, m4a, aac, wav, ogg, opus, flac)을 미디어 프로토콜에 추가했다.

### 제한

- 미리보기는 근사치다. 최종 결과는 내보내기나 "미리보기 렌더"로 확인해야 한다.
- 오디오 파형, 여러 트랙, 키프레임 편집은 아직 없다.
- 실제 Windows 에서의 재생 성능(4K, 긴 프로젝트)은 확인하지 않았다.

## 1.12.0 (2026-11-04)

영상 편집기의 타임라인을 다듬었다. 구간을 고르고 잘라내거나 남기는 기능, 클립 가장자리 트림, 여러 클립 고르기, 눈금 클릭과 끌기, 편집 단축키를 넣었다. 편집 동작은 모두 실행 취소와 다시 실행이 된다.

### 구간 선택과 잘라내기

- **눈금 끌기**: 타임라인 위쪽 눈금을 끌면 구간이 선택된다. 가볍게 누르면 재생 헤드만 옮긴다.
- **I·O 키**: 재생 헤드 위치를 구간 시작(I)과 끝(O)으로 지정한다. 버튼으로도 같은 일을 한다.
- **구간 삭제 (잔물결)**: 구간을 잘라내고 뒤의 클립을 앞으로 당긴다. 구간에 걸친 클립은 앞·뒤 조각으로 나뉜다. Delete 키로도 지운다.
- **구간만 남기기**: 구간 바깥을 모두 잘라 구간만 남긴다.
- **스냅**: 구간 끝과 재생 헤드는 클립 경계에 6픽셀 안에서 붙는다.

### 클립 편집

- **가장자리 트림**: 클립의 시작이나 끝을 끌어 줄이거나 늘린다. 최소 0.2초, 원본 길이를 넘지 않는다. 한 번 끌면 실행 취소 한 단계다.
- **여러 클립 고르기**: Ctrl+클릭으로 고르고, Delete 키나 "고른 클립 삭제" 버튼으로 한 번에 지운다.
- **단축키**: S 키로 재생 헤드 위치에서 나누고, 화살표로 한 프레임씩(Shift는 1초씩) 움직이고, Home·End로 처음과 끝으로 간다. Esc는 선택을 푼다. 입력칸에서는 동작하지 않는다.

### 실행 취소

- 클립 추가, 삭제, 분할, 복제, 순서 바꾸기, 트림, 구간 삭제, 구간만 남기기, 전환·텍스트·속성 변경, 배경 음악·워터마크·출력 설정이 모두 실행 취소와 다시 실행의 대상이다.
- 끌기 동작은 끝까지 한 단계로 묶인다.
- 프로젝트 만들기, 열기, 삭제는 실행 취소 대상이 아니다. 삭제는 되돌릴 수 없으므로 실행 취소 목록을 따로 두지 않는다.

### 제한

- **미리보기 재생이 없다.** 가운데 미리보기는 재생 헤드 위치의 원본 프레임 한 장이다. 타임라인을 실시간으로 재생하며 확인하는 기능은 아직 없다. 결과는 내보내기 후 확인해야 한다.
- 오디오 파형 표시, 여러 트랙(겹쳐 쓰는 영상이나 자막 트랙), 키프레임 편집은 없다.
- 구간 내보내기는 "구간만 남기기"로 프로젝트를 줄인 뒤 내보내는 방식이다. 원본 프로젝트는 되돌릴 수 있다.
- 실행 취소 기록은 프로젝트를 열 때마다 새로 시작한다.

## 1.11.0 (2026-11-01)

유튜브 임베드 재생을 넣었다. 이 기능에 맞춰 "외부 전송을 하지 않습니다" 원칙을 바꿨다. 기본값은 꺼짐이며, 설정에서 켜야 유튜브 서버에 접속한다.

### 원칙 변경

- **이전 원칙**: 앱은 외부 전송을 하지 않는다. 렌더러의 네트워크 연결(`connect-src`)과 외부 리소스를 모두 막았다.
- **새 원칙**: 기본은 여전히 외부 전송 없음이다. 사용자가 설정에서 "유튜브 임베드 재생 허용"을 켠 경우에만 유튜브 호스트에 접속하며, 그 밖의 외부 접속은 허용하지 않는다.
- 렌더러 CSP 에 `frame-src https://www.youtube-nocookie.com` 만 추가했다. 네트워크 연결(`connect-src 'none'`)과 스크립트 출처(`script-src 'self'`)는 그대로다.

### 유튜브

- **주소 입력**: `youtube.com/watch?v=`, `youtu.be/`, `/embed/`, `/shorts/`, `/live/` 형식을 받는다. `t=90` 또는 `t=1m30s` 로 시작 위치를 지정할 수 있다. 다른 호스트와 잘못된 영상 ID 는 거부한다.
- **재생 조작**: 재생, 일시정지, -10초, +10초, 현재 위치 표시. 플레이어의 postMessage 로만 조작한다.
- **저장 없음**: 영상은 파일로 받지 않고 플레이어에서 스트리밍으로만 재생한다.
- **네트워크 정책**: 메인 프로세스가 유튜브 호스트 요청만 설정이 켜진 경우에 통과시킨다. 허용 호스트는 youtube-nocookie.com, youtube.com, ytimg.com, googlevideo.com, gstatic.com, google.com, googleapis.com 이다. 유튜브 요청에는 앱 식별용 Referer 를 붙인다. file:// 로 연 앱은 Referer 가 없으면 플레이어가 재생을 거부하기 때문이다.
- **YouTube Music**: 공식 임베드 재생을 제공하지 않아 앱 안에서 재생하지 않는다. 버튼으로 기본 브라우저에서 연다.

### 제한

- 이 빌드의 자동 테스트는 주소 해석, 정책, 메시지 형식, CSP, 설정 흐름만 확인한다. 실제 유튜브 재생은 네트워크가 있는 Windows 에서 직접 확인해야 한다. Referer 설정이 맞는지도 그때 확인해야 한다.

- **플레이어 키보드 조작**: Space(재생·정지), ←/→(3초, Shift로 10초), , .(프레임 이동), Z(배속 초기화), X/C(감속·가속), [ ](A/B 지점), L(구간 반복), R(회전), H/V(반전). 영상 영역을 클릭한 뒤 쓴다.

### 제한

외부 자막 파일 자동 감지와 결과 포함을 추가했다.

### 추가된 것

- **외부 자막 감지**: 분석 시 영상과 같은 폴더에서 `영상.srt`, `영상.ko.srt`, `영상.ko.forced.ass` 형태의 `.srt/.ass/.ssa/.vtt` 파일을 찾는다 (최대 10개, 20 MiB 이하). 형식은 ffprobe 로 확인하고, 문자 인코딩은 UTF-8(BOM 유무)·UTF-16·CP949 를 판정한다. 파일명 태그에서 언어 코드를 붙인다 (ko→kor 등).

- **안전 규칙**: 자막 원본은 읽기만 한다. CP949·UTF-16 변환은 작업 임시 폴더의 복사본에만 한다. 분석 뒤 자막 파일이 바뀌면 `INPUT_CHANGED` 로 중단한다. 읽을 수 없는 자막은 사유와 함께 제외하고 영상 처리는 계속한다.
- 작업 상세의 "외부 자막 파일" 목록과 "같은 이름의 외부 자막 파일을 결과에 포함" 체크, 설정의 새 작업 기본값.

### 제한

- 라이브러리 미리보기 재생에는 자막을 표시하지 않는다. 자막 굽기(하드섭), 편집, 싱크 조정은 없다.
- 이미지 자막 파일(.sub/.idx)은 대상이 아니다.
- 설정 미리보기(비교 탭)와 샘플 추천 인코딩에는 외부 자막을 넣지 않는다.
