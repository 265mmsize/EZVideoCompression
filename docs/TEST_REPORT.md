# 테스트 결과

이 문서는 이 커밋 시점에 실제로 실행한 결과만 기록한다. 실행하지 않은 항목은 "미검증"이다.

## 1. 실행 환경

| 항목       | 값                                                       |
| ---------- | -------------------------------------------------------- |
| OS         | Linux 6.18 (컨테이너, root 실행)                         |
| Node.js    | 22.22.0 (테스트 러너), Electron 44.9.1 (번들 Node 24.22) |
| FFmpeg     | 6.1.1 (Ubuntu 빌드, libx264·libx265 포함, libvmaf 없음)  |
| GPU        | 없음 (NVENC·QSV·AMF 모두 사용 불가로 판정)               |
| 디스플레이 | Xvfb (xvfb-run)                                          |
| Windows    | 미사용. Windows 11 실행 검증은 하지 않았다               |

E2E 는 파일 선택 대화상자만 메인 프로세스에서 스텁으로 바꾼다. 나머지는 실제 UI 조작이다.
테스트 실행마다 격리된 사용자 데이터 디렉터리를 쓴다. 이전 실행의 기록이 섞이면 테스트가 깨진다.

E2E 는 root 로 실행되는 컨테이너이므로 Electron 에 `--no-sandbox` 를 넘겼다. 이것은 테스트 환경에만 적용되며,
앱 자체의 `sandbox: true` 설정은 그대로다.

## 6. 픽스처

모든 입력 영상은 `tests/fixtures/generate.ts` 가 FFmpeg 로 실행 시점에 만든다. 저장소에는 바이너리를 두지 않는다.

| 픽스처                               | 목적                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------- |
| `h264_sdr.mp4`                       | 기본 H.264 SDR                                                                              |
| `no_audio.mp4`                       | 오디오 없음                                                                                 |
| `multi_audio.mkv`                    | 음성 2개(한국어, 영어), AC-3 포함                                                           |
| `subtitle.mkv`                       | SRT 자막                                                                                    |
| `rotated.mp4`                        | 표시 행렬 회전 90° (ffprobe 로 확인)                                                        |
| `vfr.mkv`                            | 프레임 일부를 규칙적으로 제거한 불규칙 타임스탬프 (VFR 유사, 평균 프레임레이트는 같게 나옴) |
| `hevc_10bit.mkv`                     | 10비트 H.265                                                                                |
| `hdr_like.mkv`                       | PQ 전달 특성 태그를 가진 10비트 영상 (실제 HDR 콘텐츠가 아니라 태그 검증용)                 |
| `corrupt.mp4`                        | 손상 입력 (임의 바이트)                                                                     |
| `한글 경로 폴더/테스트 영상 (1).mp4` | 한글·공백·괄호가 있는 경로                                                                  |

합성 영상의 절감률은 일반 영상의 성능 근거로 쓰지 않는다. 이 문서의 숫자는 기능 검증용이다.

## 7. 확인한 것과 확인하지 못한 것

확인함:

- 실제 FFmpeg 로 분석, 인코딩, 검증, 확정, 취소, 중단 복구, 목표 용량 상한, 샘플 SSIM 측정, CPU 대체
- 원본 파일의 SHA-256 이 처리 전후 같음 (성공, 취소, 실패 경로 모두)
- 취소 후 잔여 FFmpeg 프로세스 0개
- Electron 창의 주요 흐름과 패키지 앱 기동 (Linux)
- 미디어 라이브러리: 전용 프로토콜 Range 재생, 인덱싱·썸네일·프레임·프록시·설정 미리보기를 실제 FFmpeg 와 Electron 창에서 확인
- 외부 자막: CP949·UTF-8 자막 파일이 MKV·MP4 결과에 트랙으로 들어가고 자막 원본은 변하지 않음 (실제 FFmpeg)
- 이미지 편집: 실제 FFmpeg 로 저장한 결과의 해상도·코덱·픽셀 포맷을 ffprobe 로 확인, 원본 불변, 화면 캡처는 xvfb 에서 PNG 생성 확인
- 번들 FFmpeg 6.0 실행 파일이 win-unpacked 에 고정 해시와 함께 포함됨
- Windows 설치 파일·포터블 생성과 오프라인 내용 검증 (설치 동작과 앱 실행은 Windows 에서 확인해야 함)

확인하지 못함:

- Windows 11 에서의 설치, 실행, 제거 (`docs/RELEASE_CHECKLIST.md` 4절)
- GPU 인코더(NVENC, QSV, AMF)의 실제 인코딩과 품질 값
- 실제 사용자 영상(카메라 원본, 방송 원본)에서의 화질과 용량
- 샘플 추천의 SSIM 기준 0.97 의 적절성 (테스트 영상 데이터셋 필요)
- 드래그앤드롭과 폴더 추가의 자동 E2E (수동 확인 필요)
- 전체 프레임 디코딩 검증과 VMAF (미구현 또는 libvmaf 부재)
- macOS 빌드
- 장시간(수 시간 분량) 영상과 대량 파일(수백 개) 처리 성능
- 1만 개 이상 폴더의 인덱싱 시간·메모리, HEVC 직접 재생이 되는 Windows GPU 환경에서의 플레이어 동작
- 외부 자막 E2E (화면 조작 자동 테스트 없음, 통합 테스트로만 확인), ASS 스타일이 있는 실제 자막 파일
- 이미지 편집기의 마우스 드래그 자르기(E2E 는 숫자 입력만), Windows 실기기의 화면 캡처(다중 모니터·배율), 실제 카메라 사진의 보정 품질
