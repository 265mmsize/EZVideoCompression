# 압축 정책

이 문서는 앱이 어떤 설정으로 무엇을 하는지 설명한다. 값은 제품의 초기 실험값이며, 샘플 추천과 테스트 영상으로 조정해야 한다.

## 1. 용어

- **무손실 / 손실**: 원본 유지 모드는 영상 스트림을 바이트 단위로 복사하므로 영상 데이터의 손실이 없다.
  다른 모드는 재인코딩하므로 손실 압축이다. 화면에서도 모드 이름과 설명으로 이를 구분한다.
- **MB**: 이 앱은 MB 를 MiB(1,048,576 바이트)로 정의하고 화면에 그대로 표기한다.
- **SSIM**: 구조 유사도(0~1). 백분율이 아니다. 화질 보존 퍼센트로 표현하지 않는다.
- **추정 / 확정**: 추정은 샘플 비트레이트나 목표값에서 계산한 범위다. 확정은 인코딩 후 검증을 통과한 파일 크기다.

## 2. 모드

| 모드                          | 영상                                         | 음성                          | 자막·첨부                                                       | 용량                                             |
| ----------------------------- | -------------------------------------------- | ----------------------------- | --------------------------------------------------------------- | ------------------------------------------------ |
| 원본 유지 (`copy`)            | 스트림 복사                                  | 호환 시 복사, 아니면 차단     | 호환 시 복사, MP4 에서 이미지 자막·첨부는 사유와 함께 제외      | 원본과 비슷하거나 더 클 수 있음 (추정 범위 표시) |
| 고품질 자동 (`quality`, 기본) | 원본 해상도, CRF                             | 호환 시 복사, 아니면 AAC 변환 | 텍스트 자막은 컨테이너에 맞게 변환, 이미지 자막은 MP4 에서 제외 | 샘플 추천 전에는 예측하지 않음                   |
| 빠른 압축 (`fast`)            | 하드웨어 인코더 우선, 없으면 CPU 빠른 프리셋 | 위와 같음                     | 위와 같음                                                       | 예측하지 않음                                    |
| 목표 용량 (`target`)          | 2-pass, 계산된 비트레이트                    | 위와 같음                     | 위와 같음                                                       | 목표 이하를 목표로 하며 검증 후 확정             |

## 3. 프리셋

프리셋은 인코더 속도와 CRF 보정만 바꾼다. 코덱과 컨테이너는 따로 고른다.

| 프리셋         | x264 속도 | x265 속도 | CRF 보정 | 의도                         |
| -------------- | --------- | --------- | -------- | ---------------------------- |
| 호환성 우선    | medium    | medium    | 0        | 재생 호환성과 균형           |
| 저장 공간 우선 | slow      | slow      | +3       | 같은 화질에서 용량 감소 우선 |
| 처리 속도 우선 | veryfast  | veryfast  | +2       | 시간 단축 우선               |

## 4. 품질 값 (인코더별로 분리)

| 인코더              | 기본 CRF/CQ               | 설명                                    |
| ------------------- | ------------------------- | --------------------------------------- |
| libx264             | 21                        | H.264 CRF                               |
| libx265             | 25                        | H.265 CRF. H.264 값을 재사용하지 않는다 |
| 빠른 압축 CPU       | H.264 23 / H.265 28       | 빠른 모드 전용                          |
| h264_nvenc          | `-cq 26`                  | 하드웨어 전용 척도. CRF 와 다르다       |
| hevc_nvenc          | `-cq 28`                  |                                         |
| h264_qsv / hevc_qsv | `-global_quality` 24 / 26 |                                         |
| h264_amf / hevc_amf | `-qp_i` `-qp_p` 24 / 26   |                                         |

샘플 추천을 적용하면 CRF 가 사용자 값으로 바뀐다. 코덱을 바꾸면 추천 CRF 는 버려진다.

## 5. 목표 용량 계산

```
목표 bits      = 목표 MiB × 1,048,576 × 8 × (1 − 0.01)      // 컨테이너 여유 1%
음성 bits      = Σ 음성 비트레이트 × 재생 길이               // 복사 트랙은 실측, 없으면 160 kbps 가정
영상 kbps      = (목표 bits − 음성 bits) ÷ 재생 길이 ÷ 1000
```

- 길이를 모르면 차단한다 (`DURATION_UNKNOWN`).
- 영상 비트레이트가 0 이하이면 차단한다 (`TARGET_TOO_SMALL`). 음성을 자동으로 빼지 않는다.
- bits per pixel 이 0.02 미만이면 화질 저하 경고를 표시한다.
- 2-pass 는 libx264·libx265 에서만 쓴다. 하드웨어 인코더는 2-pass 를 가정하지 않는다.
- 결과가 목표를 넘으면 `영상 kbps × (목표 ÷ 결과) × 0.97` 로 낮추고 다시 인코딩한다. 최대 3회다.
  그래도 넘으면 `TARGET_EXCEEDED` 로 실패한다. 초과 결과를 성공으로 표시하지 않는다.

## 6. 샘플 품질 추천 (3단계)

1. 영상 안에서 3초 구간 4곳(10%, 35%, 60%, 85% 지점)을 고른다. 짧은 영상은 구간을 줄이거나 하나로 합친다.
   구간이 서로 겹치지 않으며 범위를 넘지 않는다.
   **한계**: 움직임이 많은 구간을 골라내는 기능은 없다. 고정 위치다.
2. 각 구간을 FFV1 무손실 기준본으로 만든다.
3. CRF 후보(기본값 −3, 기본값, +3)로 같은 구간을 인코딩하고 크기와 SSIM 을 잰다.
4. 구간별 SSIM 의 **최솟값**이 0.97 이상인 후보 중 가장 작은 용량(가장 큰 CRF)을 추천한다.
   없으면 가장 높은 화질 후보를 추천하고 "기준 미달"로 표시한다.
5. 용량 범위는 구간별 비트레이트의 최솟값·최댓값을 전체 길이에 곱해 추정한다.

제약:

- 샘플 평가이며 전체 영상 검증이 아니다. 화면과 결과 모두에 이 문구를 함께 둔다.
- VMAF 는 사용하지 않는다. 이 FFmpeg 빌드에 libvmaf 가 없고, 모델·버전을 기록해야 하기 때문이다. SSIM 만 쓴다.
- 0.97 은 제품 초기 실험값이다. 테스트 영상 데이터셋과 육안 평가로 조정해야 한다.
- 추천 계산은 최대 2분이다. 취소할 수 있고, 취소하면 기록을 남기지 않는다.

## 7. 하드웨어 인코더 (4단계)

- 빠른 압축 모드에서만 사용한다. 설정 `fastUseHardware` 를 끄면 항상 CPU 를 쓴다.
- 사용 가능 판정: `ffmpeg -encoders` 에 이름이 있고, 10프레임 테스트 인코딩이 성공해야 한다. 모델 이름으로 판단하지 않는다.
- 실패하면 원인(마지막 오류 줄)을 설정 화면에 보여준다.
- 실제 인코딩 중 하드웨어 인코더가 실패하면 **같은 시도를 CPU 로 한 번 다시** 한다. 결과의 인코더 항목에 "GPU 실패 후 CPU 로 대체"가 기록된다.
- **미검증**: 인자 조합은 공식 옵션을 기준으로 작성했지만, 이 개발 환경에는 GPU 가 없어 실제 장치에서 실행하지 않았다.

## 8. 트랙 처리 정책

모든 제외·변환·차단은 사유와 함께 상세 화면의 "트랙 처리 정책"에 표시된다. 조용히 빼지 않는다.

| 트랙                                            | 원본 유지                      | 재인코딩 모드            |
| ----------------------------------------------- | ------------------------------ | ------------------------ |
| 주 영상                                         | 복사                           | 재인코딩 (또는 하드웨어) |
| 추가 영상 / 커버 이미지                         | 제외 (사유 표시)               | 제외 (사유 표시)         |
| 음성 (MP4 복사 가능: aac, ac3, eac3, mp3, alac) | 복사                           | 복사                     |
| 음성 (그 밖)                                    | 차단                           | AAC 변환 (변환 표시)     |
| 텍스트 자막                                     | MP4: mov_text 변환 / MKV: 복사 | 같은 규칙                |
| 이미지 자막 (PGS, VobSub 등)                    | MP4: 제외 (경고) / MKV: 복사   | 같은 규칙                |
| 첨부 파일(폰트)                                 | MKV: 복사 / MP4: 제외 (경고)   | 같은 규칙                |
| 데이터 스트림                                   | 제외 (정보)                    | 제외 (정보)              |
| 챕터                                            | 복사                           | 복사                     |

## 9. 영상 특성별 처리

| 특성                        | 판정           | 재인코딩                                           | 원본 유지             |
| --------------------------- | -------------- | -------------------------------------------------- | --------------------- |
| HDR 전달 특성 (PQ, HLG)     | 차단           | 차단 (SDR 자동 변환 없음)                          | 경고 후 복사          |
| Dolby Vision 메타데이터     | 차단           | 차단                                               | 경고 후 복사          |
| 알파 채널                   | 차단           | 차단                                               | 경고                  |
| 인터레이스                  | 차단           | 차단 (디인터레이스 미검증)                         | 경고 후 복사          |
| 10비트 + H.264 출력         | 차단           | 차단 (8비트 조용한 변환 금지)                      | 경고                  |
| 10비트 + H.265 출력         | 허용           | 10비트 유지 (`yuv420p10le`)                        | 복사                  |
| 4:2:2 / 4:4:4               | 경고           | 4:2:0 으로 변환 (경고 표시)                        | 복사                  |
| 회전 메타데이터             | 정보           | 픽셀 회전 후 재인코딩 (해상도 가로·세로 교환 반영) | 메타데이터 유지       |
| 평균·명목 프레임레이트 차이 | 정보           | 타임스탬프 passthrough                             | 복사                  |
| 재생 길이 불명              | 정보 또는 차단 | 불확정 진행률                                      | 목표 용량 모드는 차단 |

가변 프레임률(VFR)은 평균과 명목 프레임레이트의 차이만으로 확정하지 않는다.
재인코딩은 `-fps_mode passthrough` 로 원본 타임스탬프를 유지한다. 타임스탬프 기반 VFR 판정은 아직 구현하지 않았다.

## 10. 검증 허용 오차

- 재생 길이: `max(0.75초, 길이 × 0.5%)` 이내. 프레임 수 비교는 하지 않는다.
- 디코딩: 시작·중간·끝 지점 각 2초를 디코딩해 오류 출력이 없어야 한다.
- 복사 모드: 영상 패킷 수가 입력과 같아야 한다.
- 파일 해시: 같은 값을 기대하지 않는다. 컨테이너가 바뀌므로 해시는 원본 보호 검사(원본 쪽)에만 쓴다.
- 검증 결과에는 `basicOnly: true` 를 붙이며, 화면은 "전체 프레임 검증 완료"라고 표시하지 않는다.
